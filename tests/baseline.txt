# Known non-passing fixtures: failures AND native/browser divergences.
# One id per line, `#` starts a comment.
#
# The suite runs at ~52 known non-passes, so a raw pass/fail count carries no
# signal -- a regression hides in the noise. This file is the signal: the gate
# is "no NEW names", not "zero failures".
#
#   bun scripts/run-tests.mjs --check-baseline    # gate: exits 1 on a new name
#   bun scripts/run-tests.mjs --write-baseline    # accept current state
#
# Never regenerate to make a red run green without reading the diff. A fixture
# that starts failing is either a regression or an intended change, and only a
# human can tell those apart.
#
# MUST be recorded with BOTH hosts available. A native-only run reports zero
# divergences no matter what the browser compiler does, so a baseline taken
# without Chromium silently bakes in a single-host view and masks every
# browser-side regression. Confirm before trusting a run:
#
#   [hats build] nativeAvailable=true browserAvailable=true
#
# Recorded 2026-08-23, both hosts, against deka b32c87cae (cli 0.26.0), with
# both artifacts built from that checkout. Not 0.26.1: the harness prints the
# published CDN version, which is a different number and not a claim about the
# artifact under test.
#
# Of these, 8 are divergences -- native and browser disagree, 6 of them about
# what the parser rejects. Those are the suite's whole reason to exist; they
# are baselined as known, not accepted as correct.
